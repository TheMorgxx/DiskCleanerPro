# DiskCleaner — безопасная очистка дисков Windows

Полноценное desktop-приложение на C# / .NET 8 / WPF для анализа и безопасной
очистки кэшей и временных файлов на **всех** локальных дисках Windows (не
только C:), с сильной защитой от удаления важных данных.

Готовую сборку (один `DiskCleaner.exe`, .NET ставить не нужно) можно скачать на странице
[Releases](https://github.com/TheMorgxx/DiskCleanerPro/releases). Версия приложения задаётся в
`Directory.Build.props` (по умолчанию `1.0.0`), а при выпуске релиза берётся из тега.

## Сборка и запуск

Нужен .NET 8 SDK (с поддержкой Windows Desktop для WPF).

```powershell
dotnet restore
dotnet build
dotnet run --project src\DiskCleaner.App
```

Юнит-тесты (не требуют WPF, можно гонять и в CI):

```powershell
dotnet test tests\DiskCleaner.Tests
```

Всё сразу (restore, сборка Release, тесты) делает `build.bat`; с параметром `notest` тесты пропускаются.

При запуске учётной записью администратора приложение запрашивает UAC
(`highestAvailable`); после подтверждения категории, требующие повышенных прав
(Windows Update cache, Delivery Optimization, иногда Windows\Temp), доступны.
Обычный пользователь запускается без повышения; категории, требующие повышенных
прав, отмечены статусом «Требуются права администратора» и недоступны для выбора.

Кнопка **«Найти мусор»** ищет в известных местах кэши, временные файлы и дампы;
остальные файлы не затрагивает. Результаты показаны в разделе **«Найденный мусор»**.
Кнопка **«Что занимает место»** показывает самые тяжёлые папки и файлы на выбранных
дисках. Это просмотр; удалять можно вручную с подтверждением.

## Какие категории чистятся

| Категория | Где искать | Риск |
|---|---|---|
| Пользовательский TEMP | `%TEMP%` | Safe |
| Windows Temp | `{диск}\Windows\Temp` (только системный диск) | Safe (может требовать админку) |
| NVIDIA DXCache / DirectX Shader Cache | `%LOCALAPPDATA%\NVIDIA\DXCache`, `%LOCALAPPDATA%\D3DSCache` | Safe |
| Crash Dumps | `%LOCALAPPDATA%\CrashDumps` | Safe |
| Кэш миниатюр Windows | `%LOCALAPPDATA%\Microsoft\Windows\Explorer` (только файлы `thumbcache_*.db`/`iconcache_*.db`) | Safe |
| Браузерные кэши | Chrome/Edge/Brave/Opera/Vivaldi/Firefox — папки Cache/Code Cache/GPUCache/cache2 во всех профилях | Safe |
| Electron app cache | Общий поиск Cache/Code Cache/GPUCache под `%LOCALAPPDATA%` (Discord, VS Code, CapCut и т.п.) — эвристика | Review |
| JetBrains caches/index/log/jcef_cache/full-line | `%LOCALAPPDATA%\JetBrains\*` | Safe |
| Gradle caches | `%USERPROFILE%\.gradle\caches` | Safe |
| NuGet global packages | `%USERPROFILE%\.nuget\packages` — без сети сборка может не пройти | Review |
| NuGet HTTP cache | `%LOCALAPPDATA%\NuGet\v3-cache` | Safe |
| pip cache | `%LOCALAPPDATA%\pip\cache` | Safe |
| npm/yarn/pnpm cache | `%LOCALAPPDATA%\npm-cache`, `%APPDATA%\npm-cache`, `%LOCALAPPDATA%\Yarn\Cache`, `%LOCALAPPDATA%\pnpm-store` | Safe |
| Playwright browser cache | `%LOCALAPPDATA%\ms-playwright` — браузеры скачиваются заново (сотни МБ) | Review |
| Android build/cache | `%LOCALAPPDATA%\Android\Sdk\.temp`, `%USERPROFILE%\.android\{cache,build-cache}` | Safe |
| Unity (глобальный кэш) | `%LOCALAPPDATA%\Unity\cache` | Safe |
| Unreal Engine Derived Data Cache | `%LOCALAPPDATA%\UnrealEngine\Common\DerivedDataCache` — пересчёт может быть долгим | Review |
| Roblox downloads/cache | `%LOCALAPPDATA%\Roblox\downloads` | Safe |
| CapCut cache | `%LOCALAPPDATA%\CapCut\...\{Cache,Code Cache,GPUCache}` | Safe |
| Delivery Optimization cache | `{системный диск}\Windows\...\DeliveryOptimization\Cache` | Manual, требует админку |
| Windows Update cache | `{системный диск}\Windows\SoftwareDistribution\Download` | Manual, требует админку |
| Temp/tmp в корне диска | `{диск}\Temp`, `{диск}\tmp` — для ЛЮБОГО выбранного диска | Review |
| ShaderCache (эвристика по диску) | Поиск папок `ShaderCache` по всему выбранному диску | Review |

Safe-категории отмечаются галочкой по умолчанию (если доступны при текущих правах).
Review и Manual — никогда, пользователь должен сам их просмотреть и выбрать.
Сохранённый между запусками выбор восстанавливается только для Safe: Review и Manual при каждом
сканировании снова стартуют без галочки.
В интерфейсе уровни риска называются так: Safe — «Безопасно», Review — «Проверить», Manual — «Вручную».

## Что никогда не удаляется

- Корень любого диска (`C:\`, `D:\` и т.д.) целиком.
- `Windows`, `Windows\System32`, `Program Files`, `Program Files (x86)`, `ProgramData`, `Users` —
  для ЛЮБОГО диска, с единственными явными исключениями: `Windows\Temp`,
  `Windows\SoftwareDistribution\Download`, `Windows\...\DeliveryOptimization\Cache`, а также
  профильные папки кэшей ТЕКУЩЕГО пользователя внутри `Users\<вы>` (`%TEMP%`, `%LOCALAPPDATA%`,
  `%APPDATA%`, `.gradle`, `.nuget`, `.android`). Чужие профили и остальное внутри `Users`
  (например `Users\<вы>\Projects`) по-прежнему заблокированы.
- `$Recycle.Bin`, `System Volume Information`.
- `Documents`, `Desktop`, `Downloads`, `Pictures`, `Videos`, `Music` текущего пользователя.
- Исходники проектов, базы данных, настройки программ, `AppData` целиком, папки программ целиком —
  ничего из этого не попадает под whitelist ни одного правила.
- Содержимое любого symlink/junction/reparse point — такие элементы всегда
  пропускаются (и при подсчёте размера, и при удалении), никогда не удаляются
  и не разворачиваются, только логируются как skipped.
- Сама папка-категория (например сам `%TEMP%`) — удаляется только СОДЕРЖИМОЕ,
  никогда сама папка.
- Любой путь, добавленный пользователем в исключения (окно "Настройки"), и любая цель очистки,
  внутри которой лежит исключённый путь — такая цель блокируется целиком.

## Как работает безопасность

1. **Whitelist, не blacklist.** `CleanupRuleProvider.GetBuiltInRules()` (агрегирует
   `WindowsSystemCleanupService` + `AppCacheDetector` + `BrowserCacheDetector`) —
   единственное место, где перечислены категории, которые в принципе можно
   предложить к удалению.
2. **PathSafetyService** — единственная точка решения "безопасно ли". Путь
   нормализуется в абсолютный (`Path.GetFullPath`, защита от `..\`) и проходит:
   - блок-лист пользовательских исключений (список читается заново при каждой проверке, поэтому
     изменения из окна "Настройки" действуют сразу; блокируется и сам исключённый путь, и цель,
     внутри которой он лежит);
   - проверку существования;
   - запрет на удаление корня диска;
   - запрет, если сам путь — symlink/junction;
   - запрет пользовательских папок (Documents/Desktop/...);
   - запрет системных директорий (с точечными исключениями для одобренных
     подпапок Windows и для профильных кэшей текущего пользователя внутри `Users`);
   - **Whitelist A** — путь внутри профильных корней пользователя;
   - **Whitelist B** — путь с известным "кэшевым" именем (Temp/tmp/ShaderCache) на любом диске.

   Проверка выполняется **дважды**: при сканировании и ПОВТОРНО прямо перед
   удалением (`CleanupService.CleanOne`) — на случай, если что-то изменилось
   между сканированием и подтверждением.
3. **ReparsePointGuard** — используется `SizeCalculator` (не заходит внутрь
   symlink/junction при подсчёте размера) и `CleanupService` (не удаляет
   содержимое через ссылку и не трогает саму ссылку) на каждом шаге обхода.
4. **Удаляется только содержимое** — `CleanupService.DeleteDirectoryContentsOnly`
   никогда не вызывает `Directory.Delete` на саму папку-цель.
5. **Обязательное подтверждение** перед реальным (не dry-run) удалением —
   `ConfirmationWindow` показывает точный список путей, размеры и
   предупреждение, если среди выбранного есть категории Review/Manual.
6. **Тестовый прогон включён по умолчанию.**
7. **Ни одна ошибка доступа не роняет приложение** — весь файловый ввод-вывод
   обёрнут в try/catch с логированием в `SkippedItem`/`errors`, обработка
   продолжается.
8. **Отмена.** Сканирование и очистка выполняются в фоне (`Task.Run` +
   `CancellationToken`), кнопка «Отмена» вызывает `CancellationTokenSource.Cancel()`;
   уже найденное/удалённое до отмены сохраняется.

## «Что занимает место» и ручное удаление

Окно «Что занимает место» показывает известные места, тяжёлые папки и файлы, а также группы
папок-пожирателей. Анализ только читает диск. Удаление выбранного запускается отдельной
кнопкой; строки анализа изначально не отмечены, личные данные автоматически не выбираются.

Статусы строк:

- **«Пересоздаётся»** — известное место с пересоздаваемым содержимым. Если есть оговорка,
  она показана рядом, например «скачивается заново, нужна сеть».
- Для папок-пожирателей показывается описание группы: например,
  «Артефакты сборки Rust — пересоздаются командой cargo build».
- **«Нужно подтверждение: …»** — личные данные, содержимое папки из «Моих проектов»
  или данные профиля браузера. Этот статус важнее подписи о пересоздании.
- **«Нельзя удалить: …»** — путь заблокирован правилами безопасности, выбор недоступен.
- **«Не защищено — проверьте перед удалением»** — остальные файлы и папки, включая
  известные места без признака пересоздания. Это не рекомендация удалить их.
- После прерванного анализа папки вне индекса получают статус
  **«Анализ был прерван: содержимое папки не проверено»** и недоступны для выбора
  до повторного анализа. После завершённого анализа применяются обычные правила защиты.

В «Настройках» есть список **«Мои проекты»**. Сам корень добавленной папки и любая папка
выше него защищены от ручного удаления; удаление внутри требует подтверждения с указанием
папки проекта. Изменения списка действуют при следующей проверке пути. Исключения и проекты
сохраняются при закрытии окна настроек, в том числе крестиком.

Кнопка **«Не предлагать»** рядом с «Показать» есть во всех четырёх таблицах. Она сразу
сохраняет путь в исключениях и убирает его и вложенные строки из таблиц; при повторном
анализе они также скрыты. Строки-предки остаются, но свежая проверка перед удалением
блокирует их, если внутри есть исключение. Для отмены удалите путь из исключений в
«Настройках» и повторите анализ. Если запись настроек не удалась, интерфейс сообщает об ошибке.

После анализа найденные личные папки передаются в индекс защиты. Перед реальным удалением
личных путей в фоне собирается сводка **по всем файлам под этими путями**: число файлов,
суммарный размер, диапазон дат изменения и до пяти самых больших файлов. В окне анализа
виден статус «считаю…»; кнопка «Отмена» останавливает подсчёт и удаление не начинается.
Дубли и вложенные выбранные пути не считаются дважды. Недоступные элементы отмечаются в
сводке, поэтому она может быть неполной.

Если подсчитанный объём по личным путям составляет **10 ГБ и более** (10 × 1024³ байт),
кнопка «Удалить» в подтверждении включается только после ввода **«УДАЛИТЬ»** без учёта
регистра и пробелов по краям. Для одних только проектов или профилей браузеров слово по
объёму не требуется. Отказ в дополнительном подтверждении пропускает чувствительные пути;
остальные выбранные разрешённые пути обрабатываются. Тестовый прогон не требует подтверждений
и ничего не удаляет.

## Firefox: точечная очистка данных сайтов

Кнопка **«Firefox»** открывает отдельное окно. Приложение находит профили через `profiles.ini`
(профиль может называться как угодно и лежать вне стандартной папки), анализирует
`storage\default` и показывает данные по сайтам: размер, дату изменения, уровень риска и
что произойдёт после удаления.

- Удаляются только выбранные типы данных выбранных сайтов: **Cache API** (риск низкий),
  **IndexedDB** (средний), **localStorage** и **файлы сайта / OPFS** (высокий).
- Куки, пароли, история, закладки, расширения и настройки Firefox **не затрагиваются**: модуль
  по построению не умеет удалять ничего, кроме подпапок из фиксированного списка внутри
  `storage\default\<источник>`. Данные расширений (`moz-extension`) тоже заблокированы.
- Пока Firefox запущен (или профиль занят — `parent.lock`), **реальное удаление запрещено целиком**:
  иначе можно повредить базу квот. Закройте Firefox, включая фоновые процессы.
- Работают те же защиты, что и при ручном удалении: исключения из «Настроек», тестовый прогон,
  повторная проверка пути перед удалением и подтверждение. По желанию файлы отправляются в Корзину
  (место освободится только после очистки Корзины).
- Часть сайтов хранит состояние входа в IndexedDB/localStorage — на них вас могут попросить войти заново.
  Кнопка «Выбрать рекомендуемые» отмечает только малорисковые данные.

## Пропущенные элементы и журналы

Всё, что приложение не смогло или не должно было трогать (занято процессом, нет доступа,
symlink/junction, заблокировано правилами безопасности), не роняет работу, а попадает в список.
Кнопка **«Пропущенные элементы (N)»** показывает причину, путь и подробности. Кнопка **«Логи»**
открывает журнал текущего сеанса и папку с файлами журналов.

## Известные ограничения

- Релизная сборка — один self-contained `DiskCleaner.exe` только для Windows x64 (около 150 МБ,
  потому что внутри .NET и WPF). При первом запуске он может быть проверен SmartScreen: файл не подписан
  сертификатом.
- Используется только тёмная тема, без переключателя. Режим высокой контрастности не поддерживается.
- Системные MessageBox при ошибке открытия проводника из окна логов и при сбое
  приложения (CrashReporter), а также при ошибке сохранения настроек сохраняют системное оформление.
- Если программа запущена через учётные данные другого администратора, очищается
  профиль этого администратора. Для `dotnet run` нужен терминал от администратора.

- Защита по составу папки использует расширения и размеры файлов, поэтому возможны ложные
  срабатывания: например, ресурсы приложения могут выглядеть как личные изображения или аудио.
- Личная папка не определяется по составу, если не выполнен ни один порог: 20 личных файлов
  размером от 32 КБ каждый, либо суммарно 1 ГБ личных файлов, либо доля личных файлов не менее
  50% при размере самой папки от 100 МБ. Расширение отдельного файла проверяется независимо.
- Для папки вне индекса её собственный состав не проверяется при ручном удалении; при этом
  могут действовать другие защиты, в том числе наследование от личной папки выше по дереву.
- Если анализ прерван, строки папок вне индекса блокируются в окне анализа со статусом
  «Анализ был прерван: содержимое папки не проверено» до повторного анализа. Индекс содержит
  только распознанные личные папки, поэтому такая блокировка консервативна: она распространяется
  и на просмотренные папки, не признанные личными. Для обычного выбора нужен завершённый анализ.

- Правила Unity/Unreal покрывают только ГЛОБАЛЬНЫЙ кэш движка
  (`%LOCALAPPDATA%\Unity\cache`, `...\UnrealEngine\Common\DerivedDataCache`),
  а не кэш конкретных проектов (`ProjectFolder\Library\ShaderCache` и т.п.) —
  безопасно найти такие папки на произвольном диске без риска задеть чужой
  "Library"/"Saved" не представляется возможным без явного указания корня
  проекта, поэтому это осознанно не реализовано.
- Кэш Windows Update реально освобождается полностью только если служба
  `wuauserv` временно остановлена — программа не останавливает системные
  службы автоматически (это отдельное, более рискованное действие), файлы,
  занятые службой, будут аккуратно пропущены как skipped.
- Исключение внутри цели очистки (например `%TEMP%\keep` при цели `%TEMP%`) блокирует цель
  целиком, а не только исключённую подпапку: пока исключение в списке, эта категория не чистится.
- Поиск `ShaderCache` по всему диску (категория Review) может быть небыстрым
  на больших/сильно захламлённых дисках — используйте «Отмену» при необходимости.
- Служебные метки журналов и метка `[DRY-RUN]` в строке прогресса приходят из Core и остаются на английском
  (`DRY-RUN`, `CLEAN`, формат журнала и т.п.); русифицирован только интерфейс.
- Необработанные исключения пишутся в отдельный crash-лог `%LOCALAPPDATA%\DiskCleaner\logs\crash_….log`
  (дата, источник, версия, полное исключение со стеком). После ошибки в потоке UI приложение закрывается.

## Как добавить новую CleanupRule

1. Откройте один из трёх файлов-каталогов в `DiskCleaner.Core/Services/`:
   `WindowsSystemCleanupService.cs` (системные категории), `AppCacheDetector.cs`
   (инструменты/приложения) или `BrowserCacheDetector.cs` (браузеры) — либо
   создайте новый детектор с тем же интерфейсом (`List<CleanupRule> GetRules()`)
   и зарегистрируйте его в `CleanupRuleProvider.GetBuiltInRules()`.
2. Добавьте новый `CleanupRule`, заполнив:
   - `Category` — при необходимости добавьте новое значение в `CleanupCategory`;
   - `RiskLevel` — `Safe` только для точно известного официального пути;
     `Review` для эвристических/найденных поиском; `Manual` для системных
     категорий, требующих осторожности;
   - `DriveScope` — `UserProfile` (не зависит от выбора дисков), `SystemDriveOnly`
     (существует только на системном диске) или `PerSelectedDrive` (нужно
     разворачивать на каждом выбранном диске — используйте токен `{drive}`
     в `BasePathTemplate`);
   - `Kind` — `FixedPath` (путь известен точно) или `DynamicSearch` (нужно
     искать подпапки по `SubPathPatterns`, с `MaxSearchDepth`);
   - `RequiresAdmin` — если путь обычно недоступен без повышенных прав;
   - `FileNamePatterns` — если удалять нужно не всё содержимое папки, а
     только файлы по маске (как для кэша миниатюр Windows).
3. Больше ничего менять не нужно — `PathSafetyService` проверит путь по
   тем же правилам (профильные корни ИЛИ известное кэш-имя на любом диске),
   `SizeCalculator`/`CleanupService` подхватят новую категорию автоматически.
   Если новый путь не попадает под существующий whitelist (например, лежит
   в совершенно новом месте), нужно добавить соответствующий корень в
   `PathSafetyService._profileAllowedRoots` (для профильных путей) — это
   единственное место, которое иначе заблокирует новое правило.
4. Юнит-тесты в `tests/DiskCleaner.Tests` не нужно менять для новой
   категории — они проверяют общую логику сервисов, а не конкретный список
   правил.

## Публикация на GitHub и релизы

Репозиторий: <https://github.com/TheMorgxx/DiskCleanerPro>. Вся логика лежит в `tools\*.ps1`
(PowerShell 5.1+, который есть в Windows), а `.bat`-файлы — тонкие обёртки: двойной клик, и всё делается само.

**`1_publish_github.bat`** — выкладывает исходники. Сам создаёт репозиторий, если папка ещё не под git,
спрашивает имя/почту для коммитов, показывает список изменений, коммитит и пушит. Папки `bin`/`obj`
в репозиторий не попадают (если они уже были закоммичены — убираются из индекса, файлы остаются на диске).
Если на GitHub уже есть коммиты, которых нет у вас (например, README, созданный при создании репозитория),
они аккуратно объединяются с вашими, без force-push.

**`2_publish_release.bat`** — выпускает релиз целиком:

1. проверяет `git`, .NET SDK 8 и GitHub CLI (`gh`); при необходимости предлагает поставить `gh` через winget
   и войти в GitHub (откроется браузер);
2. сам выкладывает исходники (шаг 1), чтобы релиз всегда собирался из коммита, который есть на GitHub;
3. предлагает следующий тег (`v1.0.0`, затем `v1.0.1`, …) и проверяет, что он свободен;
4. собирает **чистую копию закоммиченного кода**, запускает сборку и все тесты, публикует
   self-contained `DiskCleaner.exe` (версия берётся из тега);
5. проверяет, что в exe нет PDB и следов вашего профиля Windows (`Users\<имя>`);
6. создаёт Release, загружает `DiskCleaner.exe` и `DiskCleaner.exe.sha256` и **проверяет на GitHub**, что файл
   на месте и размер совпадает. Если загрузка оборвалась, запустите батник с тем же тегом: он докачает файлы.

Параметры (добавляются после имени батника): `-Tag v1.2.0` — без вопроса о теге, `-Yes` — без подтверждений,
`-DryRun` — всё собрать и проверить, ничего не публикуя, `-SkipTests`, `-IgnorePrivacy`.
Пример: `2_publish_release.bat -Tag v1.1.0 -DryRun`.

Дополнительные запрещённые строки для проверки exe можно задать переменной среды
`DISKCLEANER_EXTRA_FORBIDDEN` (через `;`, от 4 символов).

Запасной вариант: если на вашем ПК релиз не получается, на GitHub откройте **Actions → Release (manual) →
Run workflow** и введите тег; релиз соберётся и опубликуется на серверах GitHub.

Если что-то не получилось, скрипт пишет понятную причину (`[FAILED] ...`) и не оставляет репозиторий
в промежуточном состоянии: после ошибки можно просто запустить его снова.
